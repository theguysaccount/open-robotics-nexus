GitHub data read 2026-10-27. Home fit is a curated 0–100 judgement of usefulness for a low-cost home robot.

Method

Every night a GitHub Actions job reads each repository's metadata, latest release, commits from the last 90 days and full file tree through the GitHub REST API. An artifact counts as present when the file tree matches its rule:

  • Code: source files (.py, .cpp, .c, .rs, .js, .ts, .go, .ipynb and similar)
  • CAD: mechanical files (.step, .stp, .stl, .3mf, .f3d, .fcstd, .sldprt, .iges, .scad, .dxf…) or a cad/ or stl/ folder
  • BOM: a file or folder named BOM, bill of materials or parts list
  • Docs: a docs/ or documentation folder, or a docs-site config (mkdocs.yml, docusaurus, Sphinx conf.py)
  • Firmware: a firmware/, arduino/, esp32/ or similar folder, .ino files, or platformio.ini
  • Sim: robot descriptions (.urdf, .xacro, .mjcf, .sdf, .usd) or simulator code (MuJoCo, Isaac, Gazebo, PyBullet)
  • License: a LICENSE or COPYING file, or a license GitHub recognises

Only what is inside the repository counts: CAD on Onshape, docs on a separate site and code in submodules or other repositories don't. The curated scores on each page are a separate human review. To dispute a result or add a project, open an issue.
